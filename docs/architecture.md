# 架构与数据流

## 输入与不可变文档模型

`input.py` 严格读取 UTF-8；`parsing.py` 以锁定的 Pandoc reader 解析 Markdown 或纯文本。`domain/` 保存不可变文档、内容清单、来源位置、可撤销修复及局部格式。原文和当前内容分开记录，解析、预览及导出使用明确版本快照。

## 转换与校验

`conversion/` 根据规范化文档生成写入计划，逐项检查公式能力，写出临时 DOCX，并验证段落、列表、表格、超链接和 OMML。后处理按对象和 run 定向修改，避免用 paragraph.text 重写复杂段落。无法可靠转换的公式可见降级；内容完整性不确定时停止提交。

## 预览与排版

`live_preview.py` 和 `ui/preview_panel.py` 使用本地 Qt WebEngine、MathJax 和静态资源。预览与导出共享结构与样式。预览采用版本键、页面 generation、防抖和一个最新等待槽，丢弃过期结果；不模拟 Word 精确分页。局部格式保留选区锚点，正文变化后只在定位可靠时重新关联。

本地页面使用固定 CSP、资源白名单、导航与权限限制。正文中的远程资源不会自动加载，没有面向页面的任意 Python 执行桥接或 HTTP 服务。

## 导出与文件安全

`exporting/` 协调快照、工作线程、取消、期限、临时目录和输出事务。先完成内容检查，再尝试安全提交。无法可靠替换已有目标时要求另存；清理失败被单独追踪，可在后续重试。

## 状态与恢复

`storage/` 将草稿、备份、设置、个人样式和诊断放在当前用户的应用数据目录。草稿使用防抖、单写入者和同目录原子替换，保留上一份成功快照。坏文件被隔离保留；清空与关闭操作遵守写入顺序。单实例通过锁与本地通信协调。

## 资源与平台

`ResourceLocator` 明确区分源码资源、冻结资源和用户可写目录，不从 PATH 隐式寻找 Pandoc。Python 与资源版本分别由 requirements.lock 和 vendor-manifest.json 锁定。运行时不下载资源；首次准备环境由开发者显式执行工具。
